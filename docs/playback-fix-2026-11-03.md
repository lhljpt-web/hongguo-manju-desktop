# 2026-11-03 原生播放恢复 · 0.1.2

## 修正后的原因判断

扩大公开库查询后，找到 [tsukiyo-zero/hongguoTV 的 11 月 2 日接口迁移记录](https://github.com/tsukiyo-zero/hongguoTV/blob/main/docs/superpowers/specs/2026-11-02-playinfo-video-tab-api-design.md)和[当前取源实现](https://github.com/tsukiyo-zero/hongguoTV/blob/main/kotlin-tv/core/src/main/kotlin/com/hongguotv/core/ContentRepository.kt)。其 GET 播放路径不同于此前反复对照的旧 POST 路径。这是本轮有效线索，感谢该项目公开实现与实测记录。

本机沿用同一个匿名身份、相同网络和版本参数，旧 `POST /novel/player/multi_video_model/v1/` 为空，新 `GET /reading/bookapi/video_tab/multi_video_model/v1/` 对第 1、78、155 集均返回 code 0 与各自完整模型。**对本次样本，更新请求路径、方法和参数位置足以恢复；此前没有证据将旧 SDK 差异认定为根因。** SDK 差异仍是初始调查事实，但不是本轮修复内容。

不能据此断言旧端点对所有地区和客户端都永久停用，也不代表新端点长期保证可用。此前的失败实验和推测保存在[初始调查](playback-investigation-2026-11-03.md)，不回写失败记录为成功。

## 改动

- 内容接入对上层仍提供相同的单集取源接口；传输层改为 GET，并将 `video_id`、`video_id_type`、`device_level`、`need_all_video_definition`、`need_mp4_align`、`use_os_player`、`video_platform`、`source`、`from_video_id` 放在 query 中。
- 沿用本机持久化身份和已验证版本参数，不复制参考项目的设备号，不轮换身份，也不更新或替换签名 SDK。
- 严格读取 `data.video_model_data[所选分集ID].video_model`。目标不存在即失败，绝不取第一条或其他集；继续使用原有轨道、时长、加密格式和大小校验。
- 同时识别大写 `Code` 与 `BaseResp.StatusCode` 的业务错误，避免把错误对象当成合法模型。
- 现有缓存、续传、进度、播放界面、搜索和用户确认更新流程保留。原生业务错误明确显示；空结果时仍有原有官网公开兼容路径，不拿首集预览替换后续集。

请求形状属于协议事实，代码按本项目既有结构独立实现；未引入参考项目的身份轮换、第三方解析服务、设备标识、Cookie、SDK 或安装包。参考仓库标注 GPL-3.0，本项目同为 GPL-3.0-only。

## 自动与桌面检查

原协议回归先在旧 POST 实现失败，再在新实现通过。全套 186 项自动测试、类型检查及生产构建通过；覆盖无 POST 正文、必需 GET 参数、身份复用、目标集精确匹配、缺失模型和业务错误。实际生产程序的桌面验证结果见本次发布说明。

第一次线上桌面连播验收在第 2 集遇到连接来源超时，测试失败已保留。网络取源与界面验收分别记录；随后界面验收使用本轮真实获取的完整媒体验证换集、全屏、定位与续播，不把已有缓存成功冒充网络取源成功。

`QA_SEED_PROFILE=本轮冷取源输出目录 node scripts/video-tab-ui-qa.mjs` 在真实 0.1.2 打包程序中通过：分享导入后第 1→2→3 集产生实际 ended 并自动连播，同一全屏容器保持；第 78 集从 0.323 秒实际解码，第 78→79 集自然连播；第 155 集实际解码，定位 12 秒后退出重开从 12.622 秒续播。视频均为约 1920×1080，音频解码字节大于 0，无页面错误，本机身份未变。另预先准备了第 3、79 集供连续播放验证，不将它们计入六集冷取源完整解码表。

安装包 181,839,056 字节；ASAR 内主进程、preload、HTML、JS 和 CSS 与验收构建逐字节一致。`release:verify` 的版本、SHA-512 和 GitHub 更新目标通过。实际打包程序的独立更新测试也通过：启动只提示、拒绝不下载、明确点击后下载一次并等待安装确认。该测试未执行测试安装文件，不改正式更新源。

安装包的 SDK、更新目标及元数据摘要校验按既有发布流程执行。测试使用 `outputs/` 隔离 profile，不修改用户正式安装或资料；不上传设备身份、媒体地址、签名、密钥或媒体文件。本轮未在全新 Windows 机器上重做安装验收。

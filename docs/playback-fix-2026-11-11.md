# 2026-11-11 播放取流恢复

## 诊断

当日隔离巡检中，搜索、榜单和详情正常，原生播放 GET 与登记后 POST 多次返回 HTTP 200 空正文；官网备用源部分只提供 360p，不能视作全集播放恢复。

匿名设备登记偶尔返回 15 位正整数标识，而登记解析器要求至少 16 位，导致真实登记结果在播放请求前被拒绝。单独修正长度后，旧 POST 仍会返回空正文，因此这不是唯一原因。

## 修复

登记入口现在接受已观察到的 15–20 位正整数设备和安装标识。既有持久身份播放失败后，客户端以新登记身份重试 `video_tab` GET；该接口对本轮样本返回目标分集模型。若 GET 仍为空，再为既有签名 POST 登记一个新身份。非空业务错误、错误模型和 HTTP 错误不会被降级成另一个请求结果。

video-tab 参数及逐请求登记策略参考 [jackotom/hongguo-drama 当前公开实现](https://github.com/jackotom/hongguo-drama/blob/da538cd9e7ece6e45bb057875189aec8b26712bf/src/native/app-source.js)。本项目只采用请求形状和调用顺序，没有复制该文件的签名实现或身份数据。

## 验收与边界

使用隔离 profile 和空媒体缓存，通过正式 `Transport`、`ContentProvider`、`MediaCache` 与随包 FFmpeg，对两部榜单作品各抽查第 1 集、中间集和末集。六集均取得 1080p `bytevc1` 资源，完整下载并解码至源时长末尾；Range 206 和 1,024 字节响应通过。

旧 155 集历史样本第 78 集本轮取得播放模型，第 155 集仍返回空响应。尚未验证该作品全部分集，也未人工试听；平台接口变动仍可能影响后续请求。

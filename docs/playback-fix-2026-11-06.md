# 2026-11-06 播放接入调查与 0.1.3

## 已修正与尚未恢复的范围

0.1.2 的 GET 请求没有播放专用签名。参考 [hongguoTV 的 11 月 5 日修复](https://github.com/tsukiyo-zero/hongguoTV/commit/a5b2587440242fd17f7f92d14a9c841b7c87c21f)，本轮补全与最终 query、设备 ID、版本、分集和时间戳绑定的签名。沿用本机安装身份，保留原有目录签名 SDK，不将海外 SDK 的签名直接套在播放请求上。

匿名登记补充了公开协议中的 `sig_hash` 应用指纹。单变量实验曾从无效登记恢复为有效登记；后续仍观察到登记失败和部分已登记身份持续空响应，因此不能将所有故障归因于这一个字段，也不能承诺登记始终成功。

播放收到空正文时依次尝试 b、hl、lf 三个已知来源域名，每次重新签名。非空业务错误、缺失目标模型、HTTP 错误和网络异常仍直接报错；既有的未登记身份只允许一次登记恢复。**曾实验给已登记身份重新登记，但本机失败样本未恢复，该改动已撤回；正式代码不自动反复轮换身份。**

原《末世躺赢指南：到末世十年后第一季》详情接口与官网均从 155 集缩减为 3 集，其 ID 对应旧列表第 43、67、83 集。原第 78、155 集在本轮有效身份下仍只返回无目标模型的数据。用户曾报告手机官方 App 仍能播放，但之后无法重新找到并提供新分享链接，因此未能核实手机当前作品/分集映射。不能断言作品已下架，也没有修复这部作品的全集接入；没有拼回旧列表、替换作品或把这 3 集当作全集恢复。

另外发现 Electron 44 使用的 BoringSSL 不提供原生 SM3，普通 Node.js 的通过结果不能直接代表桌面运行时。已采用固定版本 sm-crypto 0.5.8 的 MIT 许可 JavaScript SM3 实现，与原生实现的签名离线向量完全一致，并增加“原生 SM3 不存在”的回归。

## 续播保护和桌面回归

来源不再列出上次观看的分集时，以前 `selectEpisode` 会自动退到第一集，可能在继续观看时覆盖旧记录。本轮改为保持未选中状态，明确提示原分集缺失并保留历史；用户手动选集后仍可播放。不按旧集号猜测映射，也不清空缓存、收藏或观看进度。

`npm test` 共 192 项（25 JavaScript + 167 TypeScript/播放状态）通过；类型检查、生产构建通过。回归先观察缺少签名、缺少登记指纹、无空响应换路和错误续播选择的失败，再实现对应改动。签名离线向量来自上游算法、合成身份、固定时钟/随机数，不包含真实身份或媒体参数。

`node scripts/continuous-playback-qa.mjs` 在真实主进程、preload、renderer、IPC 和媒体缓存上通过；内容提供者使用本地 H264/AAC 测试片，不能用这个结果替代上表的联网验证。覆盖质量切换、2 倍速、音量、全屏跨季、画中画、睡眠停止、推荐失败重试、重启偏好，以及新增的“历史分集不存在时不自动替换；手动选集可播放”。报告：`outputs/continuous-playback-qa-1793926969652/report.json`。

所有测试均在独立输出目录运行，不修改用户正式安装与真实资料。未在全新 Windows 电脑重复安装验收。签名算法来源、适配差异和 GPL-3.0 许可见 [vendor/NOTICE.md](../src/main/vendor/NOTICE.md)。

实际官网搜索两页各 10 条、目标作品匹配和关闭取消检查也通过：`outputs/search-browser-qa-1793927191354/report.json`。安装包中主进程、preload、HTML、JS、CSS 与验收构建逐字节核对，并随包保留本项目 GPL 许可、算法来源说明和 SM3 依赖 MIT 许可。

# 2026-11-03 播放资源不可用调查

**后续进展：** 扩大公开库检索后找到 `video_tab` GET 播放路径，同一本机身份已取得第 78、155 集的正确模型，并用本项目实际媒体流程完整解码到结尾。此前“尚未恢复”的段落保留为调查过程，不再代表当前结果；后续验证见[播放恢复记录](playback-fix-2026-11-03.md)。

## 初始调查结论（已被后续实测补充）

0.1.1 搜索与详情正常，但原生播放没有返回目标分集模型；官网兼容接口也不提供样本第 78、155 集。**尚未恢复完整播放，不发布声称播放已修复的新安装包。**

故障位置已缩小到资源获取层，发生在媒体下载、转码和 Electron 视频解码之前。现有结果不能确定服务端是按版本、设备、签名、网络还是其他规则拒绝请求，也不能证明“官方全面停服”或“账号被封”。

用户随后确认：**同一网络下官方手机 App 可以正常播放第 78、155 集**。这是用户提供的对照结果，不是本机抓取到的成功请求。它进一步支持桌面请求适配不兼容这一判断，不能据此认为作品已下架或服务器整体故障。

用户补充 App 显示 `Ver 7.4.0`；操作系统、准确应用名称及完整构建号尚未确认。因此以下 `74032 / 7.4.0.32` 仅为对照假设，不能当作用户手机实际构建号。

用户随后确认使用安卓手机，但暂时无法连接电脑。电脑已准备 Google 官方 Platform Tools；只读设备枚举结果为 0 台，未执行手机安装、设置变更或采集操作。因此仍未取得官方 App 成功播放请求。

### 用户版本补充后的对照

当日重新查询[短剧分发页](https://a.app.qq.com/o/simple.jsp?pkgname=com.phoenix.read)与[漫剧分发页](https://a.app.qq.com/o/simple.jsp?pkgname=com.kylin.read)，两者公开 Android 分发信息均为 7.4.3.32。它不能证明用户 `7.4.0` 属于其中哪个应用或系统。

旧身份分别请求 73532、推测的 74032、分发页确认的 74332，第 78 集均为 HTTP 200、0 字节。隔离的 74032 登记未取得有效标识。74332 登记首次也未通过，后续取得有效本机设备／安装标识，但用该同版本新身份请求第 78、155 集仍均为 200、0 字节。登记成功不等于播放上下文已完整。

还使用已静态审查的参考项目 Python 请求实现，以同一本机新身份对照 74332 和推测的 74032：第 78 集均为 HTTP 200、0 字节，没有目标模型。

另发现登记返回 `device_token`，参考请求实现支持 `x-tt-dt`，但当前客户端只持久化设备／安装标识。为检验该差异，尝试一次单独令牌对照及一次重试；登记响应虽含令牌，却未通过有效设备标识校验，未形成可用的同身份“有令牌／无令牌”对照。**令牌是否必要仍未验证**，没有将失败登记的令牌混入其他身份，也没有把此假设合入正式代码。

同一首集请求在 Node fetch 和 Electron net.fetch 中也均返回 200、0 字节。因此只更换网络栈不能恢复，搜索修复采用的浏览器方式不能直接推广为原生播放修复。

另从当日推荐榜选择两部作品交叉核对：`7700941738487073817`《重生螳螂，觉醒无限吞噬进化》和 `7693516944581872664`《东北后妈，整顿全家》，各自第 10 集原生请求同样 `API_EMPTY`。这排除了本次仅与单个样本分集有关的解释，但不代表所有作品均不可用。

从前述应用宝分发页取得 `com.phoenix.read` 7.4.3.32 的 APK，仅静态读取，未安装或执行。文件 150,181,580 字节，MD5 与分发元数据的 `10e6f13f053fda6bba35e28182a6571d` 一致，SHA-256 为 `36881d2b029fb223ac0703bd0326485abbb23672cff02af2f1f4cacf9633dad2`。

包内提供 `lib/armeabi-v7a/libmetasec_ml.so`，3,306,768 字节，SHA-256 为 `127b052e70a81607b37580c4942c775d88907fc2cc3be105814b453ea77dd43f`；没有 arm64-v8a 原生库。该签名库与已有独立漫剧 7.4.0.32 APK 中的同名库逐字节一致，但与桌面当前使用的海外版 64 位旧库不同。这只能确认组件来源、架构差异，不能证明替换二进制即可工作；原有 64 位函数偏移不能直接套在此 32 位库上。

静态 DEX 确认应用 ID 为 8662、构建号为 74332。包内仍声明 `/novel/player/multi_video_model/v1/`、`/novel/player/video_model/v1/` 及场景预加载路径，未发现可凭接口改名直接恢复的依据。`GetVideoModelRequest` 的序列化字段包含 `video_id`、`biz_param`、`content_type`、`mixed_video_id_map` 和 `NovelCommonParam`；字段声明不能证明实际请求包含了哪些值，未将未知字段猜测写入正式请求。

目前可独立开展的静态对照已保存于 `outputs/playback-2026-11-03/version740/`。手机暂时无法连接不影响这些静态结论，但缺少成功请求时，仍不能验证当前 SDK 的完整初始化上下文和运行时请求差异。
